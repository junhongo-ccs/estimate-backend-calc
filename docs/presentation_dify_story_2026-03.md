# 発表構成・台本

## タイトル案

- UIUXチーム起点で、AI見積を業務ロジックまで育てた話
- 非エンジニアが Vibe Coding で、UIUX 見積まで乗る Dify PoC を作った話
- AI のそれっぽさを検証で越えて、提案に使える見積システムにした話

## この発表で一番伝えたいこと

- 出発点は「UIUXチームが案件の前段から提案に入れるようにすること」だった
- 開発営業だけでは弱くなりがちな UIUX フェーズの見積を、提案に組み込める形にしたかった
- チームに開発者がいない中で、自分が Vibe Coding で PoC をここまで育てた
- AI は最初それっぽく振る舞ったが、UIUX 見積を本当に計算に反映してはいなかった
- そこを Codex と一緒にしつこく検証し、RAG と Python ロジックを詰めて、UIUX 見積が実計算に乗るところまで持ってきた

## 発表の芯

- 自分はエンジニアではない
- それでも、UIUX チームの提案余地を増やすために AI 見積システムを実装した
- 価値は「チャットが動くこと」ではなく、実務寄りの見積・採算ロジックに UIUX フェーズを接続したこと
- 今回の Dify では
  - 入力 UI
  - Python による deterministic 計算
  - RAG による社内基準文書参照
  - LLM による内部報告書整形
  - 結果に対する追加質問
  まで一気通貫で回せた
- 発表では安定性と機密配慮を優先し、録画中心で見せる

## 今回見せる完成像

今回のデモで見せるのは次の 4 点である。

1. 条件入力で見積結果が変わる
2. UIUX フェーズも見積に加算される
3. 結果に対して追加質問ができる
4. 回答が社内基準文書を引用しながら説明される

- 本番デモは録画を基本とする

  - 社内機密性の高いロジックとナレッジを含む
